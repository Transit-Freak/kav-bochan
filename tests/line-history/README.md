# בדיקת "הקו בזמן" בדפדפן

`ui.mjs` פותח את `line-history/` ב-Chromium, על נתונים קבועים וקטנים, ועובר על הדברים העיקריים בכלי.
המטרה: אם הבדיקה עוברת לפני שינוי בקוד ואחריו (למשל פיצול של `app.jsx` לכמה קבצים), הכלי עדיין עובד.

רצה ב-GitHub על כל PR שנוגע בקוד של הכלי (`line-history/`, בלי `data/`), בבדיקה או בנתונים הקבועים —
ה-workflow `.github/workflows/line-history-tests.yml`. לא רצה על עדכוני הנתונים.
היא לא מחליפה את `tools/check_line_history_ui.mjs`, שרצה ב-main על הנתונים המלאים.

| חיפוש קו | קבוצה לקו 146 עם כל החלופות שלו, המפעיל והמק"ט בשורה, "חלופה בוטלה", חיפוש בשתי מילים, חיפוש בלי תוצאות |
| עמוד הקו | הכתובת, היעד והפרטים; ציר הזמן מהחדש לישן, התחנות שנוספו ושורת המקור; סינון לפי סוג ("הכול", כיבוי סוג) ולפי חודש; המפה ומספר התחנות; הלו"ז המלא; בחירת גרסה קודמת; מעבר לכיוון השני; חזרה לחיפוש |

| שינויים לפי יום | כפתורי השנים והחודשים, כותרת לכל יום עם מספר השינויים, שורה מקופלת של שינויים קטנים, בחירת יום, סינון לפי קו, חודש קודם, פתיחת קו וחזרה לאותו חודש |

| עמוד תחנה | קישור ישיר (`#stop=36356`): סוג התחנה, הקווים שעוצרים בה היום, ציר הקווים, מעבר מהתחנה לקו |
| התפריט ⋯ | שש השורות, מעבר לתצוגה הקודמת — חיפוש, עמוד קו ו"שינויים לפי יום" עובדים גם בה |

בסוף נבדק גם: שאין שגיאת JavaScript בדף, שאף קובץ של הכלי לא חסר (404), ושכל קובץ בנתונים הקבועים נטען לפחות פעם אחת
(אם כתובת של קובץ נתונים השתנתה בקוד — הבדיקה נכשלת).

הדף נטען כמו באתר: `app.jsx` מקומפל בדפדפן ב-Babel מ-`vendor/`. השעה קבועה (22.11.2026) והרשת החיצונית חסומה
(אריחי מפה, גופנים, התראות, ריפו הארכיון). לא משווים פיקסלים.

## הרצה מקומית

משורש הריפו:

```
npm i --no-save --prefix /tmp/lh playwright leaflet@1.9.4
NODE_PATH=/tmp/lh/node_modules node tests/line-history/ui.mjs
```

כ-15 שניות. `CHROME=/path/to/chrome` — דפדפן אחר (ברירת המחדל: Chromium של Playwright, ואם אין — `/usr/bin/google-chrome`).
כשמשהו נכשל מודפסת רשימת בעיות בעברית, וקוד היציאה 1.

## הנתונים הקבועים

`tests/fixtures/line-history/data` — באותו מבנה של `line-history/data`, כ-130KB: קו 146 וקו 145 (סופרבוס, חולון) עם כל החלופות,
שני חודשים של 2026, צילום 07.2012, שלושה חודשים של צילומי אתרי מידע, כמה הודעות של דן ואגד, ותחנה אחת (36356).
נתוני 2012 של מגיעים (`magihim-2012/`) לא חלק מהבדיקה.

בנייה מחדש (מעתיק מ-`origin/main` עם `git show`, קובץ-קובץ, בלי להוריד את תיקיות הנתונים):

```
git fetch --depth 1 --filter=blob:none origin main
python3 tests/line-history/make_fixtures.py
```

אחרי בנייה מחדש הנתונים משתנים, ולכן צריך לעדכן את הקבועים בראש `ui.mjs` (`LINE`, `OTHER`, `STOP`) ולהריץ שוב.
רוב הציפיות מחושבות מהקבצים עצמם (מספר השינויים בכל יום, מספר ההודעות, רשימת החלופות), כך שבדרך כלל מעט משתנה.
