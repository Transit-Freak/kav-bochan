# בדיקות קו פח

בדיקה אחת בדפדפן — `tests/kavpach/app.mjs` — לקו פח, לקו המוזהב (אותו קוד, `KavPach.jsx`) ולדף הבית.
רצה ב-GitHub על כל PR שנוגע בקוד של הכלי, בדף הבית או בבדיקה (`.github/workflows/kavpach-tests.yml`),
ולא על עדכוני הנתונים. המטרה: אם היא עוברת לפני שינוי פנימי בקוד (למשל פיצול קובץ גדול) ואחריו — הכלי עובד כמו קודם.

## איך זה עובד

- שרת מקומי קטן מגיש את הריפו. קובצי הנתונים (`data-*.json`, `kavpach-*.json`, `bus/data/deadhead.json`) מגיעים
  מ-`tests/fixtures/kavpach` — 84 קווים (ערד, דימונה, שדרות, קרית מלאכי ועוד שישה קווים חזקים), בערך 1MB.
- `KavPach.jsx` מקומפל בזמן הבדיקה, ודף הבית הקבוע ב-`index.html` נבנה מ-`home/home.js` — כמו ש-`tools/build_kavpach.mjs`
  עושה ב-main. כך נבדק הקוד שב-PR גם כש-`KavPach.js` ו-`index.html` עוד לא נבנו. עם `BUNDLE=1` נבדקים הקבצים הבנויים שבריפו.
- השעה בדפדפן קבועה (22.11.2026), הרשת החיצונית חסומה, ולא משווים פיקסלים.
- כל בעיה נכתבת בשורה בעברית. אם יש בעיה אחת לפחות — קוד יציאה 1.

## מה נבדק

| שלב | מה |
|---|---|
| `home` | דף הבית: כרטיס לכל כלי ב-`GROUPS` של `home/home.js` (שם, תיאור, סמל, סדר), הכותרת עם `COUNT`, ו-`COUNT` שווה למספר הכרטיסים; דף הבית לא מוריד את הנתונים של קו פח; לחיצה על הכרטיס של קו פח ושל הקו המוזהב פותחת את הכלי, ו"חזרה" מחזירה |
| `list` | קו פח, "קווים לא יעילים": המסך הראשון עולה מהקובץ המוכן לפני לוח הזמנים; הציונים אחרי טעינת שאר הנתונים זהים; 30 כרטיסים ו"הצג עוד"; מיון; סינון לפי ציון, מחוז, קטגוריה וחברה; חיפוש קו (מספר, מק"ט, כמה קווים, קו שלא קיים); חיפוש עיר; "ציון מ-"; הגדרות הניקוד (נשמרות אחרי טעינה מחדש); ייצוא לאקסל (שורה לכל קו); קישור לקו (`#פח/קו/…`), גם לקו שירד מהרשימה; "חפש הזדמנויות התייעלות" |
| `tabs` | ניתוח אזורי (לפי עיר ומחוז, "צפה בקווים אלו"); כל הנסיעות (עיר, נסיעות עמוסות, מיון, סוג קו, "הצג עוד"); אלגוריתם ייעול (כל הקווים, קו אחד, אקסל); נסיעות תפעוליות (הטבלה, פתיחת שורה, כניסה ישירה ללשונית); על המערכת |
| `nopre` | בלי `data-lines.json`: הרשימה מחושבת בדפדפן (`kavpach-core.js`) |
| `golden` | הקו המוזהב: הרשימה, כל הלשוניות, "חפש הזדמנויות הרחבה", קישור לקו |

בכל השלבים: אין שגיאה בדף, אין `console.error`, ואין קובץ מקומי שלא נמצא.
מה שיצא (אילו קווים ובאיזה ציון, הטקסט של הכרטיסים, הטבלאות והכותרות) מושווה ל-`snapshots.json`.

## הרצה מקומית

```
npm i --no-save --prefix /tmp/kp playwright
NODE_PATH=/tmp/kp/node_modules node tests/kavpach/app.mjs
```

כשצריך — `npx playwright install chromium`, או `CHROME=/usr/bin/google-chrome` לדפדפן שכבר מותקן.
ההרצה לוקחת בערך דקה וחצי. `ONLY=list,tabs` מריץ רק חלק מהשלבים.

## אחרי שינוי מכוון בכלי

שינוי בטקסט, בניקוד או בסדר משנה את התמונה-במילים, והבדיקה תיכשל עם השורה הראשונה שהשתנתה בכל קטע.
אם השינוי רצוי:

```
UPDATE_SNAPSHOTS=1 NODE_PATH=/tmp/kp/node_modules node tests/kavpach/app.mjs
git diff tests/kavpach/snapshots.json
```

קוראים את ה-diff, מוודאים שרק מה שהתכוונתם אליו השתנה, ומוסיפים את הקובץ ל-PR.

## הנתונים הקבועים

`python3 tests/kavpach/make_fixtures.py` בונה אותם מחדש מ-`origin/main` (קורא כל קובץ ב-`git show`, בלי להוריד את תיקיות הנתונים).
אין צורך להריץ אותו בשגרה: הנתונים קבועים בכוונה, כדי שהבדיקה תראה רק שינויים בקוד. אחרי בנייה מחדש מעדכנים את התמונה-במילים,
ובודקים שהקווים שהבדיקה מחפשת בשמם (688, 4, מק"ט 10688 ו-39080) עדיין מתאימים.
